# 行为评测

[案例集](cases.json) 的 request 给评测 Agent；skill 和 observables 留给评审者。自然请求只提供技能名与描述，自行选择；显式请求提供指定技能和必要原始输入。使用独立临时工作目录，记录测试前后文件清单。每例独立上下文，不提前提供标准答案。

观察实际回复、是否写入、运行退出码和可打开的产物。对确认不足的情况检查有没有未授权文件；对预览实际尝试筛选/点选；对改造比较修改前后同一操作与数据结果；对工具失败确认它是否报告证据与阻塞原因。不能把元数据校验或关键词匹配当作行为测试。当前实际执行与未执行项见[验证记录](../docs/validation.md)。

2026-11-11 新增 negative-web-prototype、approved-scope-reuse、audit-no-material，分别检查网页任务不误触发、沿用已有批准和缺少材料时的证据边界，目前均待模型运行。approved-scope-reuse 需另附已经确认的前文和真实 Qt 工程副本；不能把这些夹具说明或 observables 当作用户请求交给被测 Agent。

每次记录案例 ID、客户端与模型、技能快照、输入夹具、实际动作、产物位置、逐项结果（通过/失败/未执行）及证据。修改 description 后优先复验易混淆的自然请求；显式调用成功不能代替自动触发检查。保留失败样例用于下一轮对照。
