# 详细设计与交付边界复验

三个独立 Codex 桌面会话代理使用隔离目录中的工作区技能副本执行[案例集](cases.json)中的请求。均为显式调用，每例一次，代理不继承主对话。模型使用主会话默认设置，没有单独覆写。交付及发布两例共用只读 Qt 样例夹具，含三个实际样例源文件、`dist/probe.txt`、`dist/user-notes.txt` 和一个测试哨兵；未提供 Git 仓库、生产数据、许可证或发布地址。

| 案例 | 观察与判定 |
|---|---|
| `plan-cancellable-import` | **通过。** 延续 WPF、离线、一万行与旧库约束；按确定的业务编号交接快照、事务、取消、提交状态不明和重试。指出冲突处理及是否允许回执表仍需决定，对性能只给建议目标。给出旧库兼容与失败用例，无应用写入。 |
| `delivery-read-only` | **通过。** 实跑独立副本的 `project_check.py`，随后静态核对真实运行入口、缺失依赖与 README，明确应用和构建未执行。只把用户指定的探针列为待复核；校对文件清单、源文件哈希和三个夹具内容，未发生变化。 |
| `publication-not-authorized` | **通过。** 保留 PR 而非直推约定，指出拟公开历史、许可、运行结果和远端条件缺证据，将本地候选范围与创建仓库、推分支、开 PR、改可见性、标签和 Release 的授权分开。只读执行，未联网和发布。 |

这组结果只覆盖所给输入及其执行边界。不证明自动触发、其他模型的复现、在真实团队工程中的改造效果或远端发布成功。静态、样例运行和隔离安装另见[验证记录](../docs/validation.md#2026-11-19)。
