# 桌面界面操作走查

从主任务决定信息密度。浏览型页面可留白；重复处理记录时优先分栏、可调整列宽的表格、行选择、批量操作和快捷键。窗口缩小后按优先级折叠次要栏，保持选中、滚动位置和主操作可达。右键菜单提供同一命令的可见或键盘入口。

集中管理语义色（表面/正文/弱化/强调/错误）、字体、圆角、边距、图标尺寸与动画参数。先用系统字体和缩放单位；透明只用于可读性稳定的区域。Windows 10、关闭透明、高对比度、节能或远程会话时使用不透明表面与系统色。不要用颜色作为唯一状态提示。

逐一检查正常、悬停、按下、选中、焦点、禁用。焦点环在亮暗表面均清楚，禁用操作应有可理解的前提。业务状态覆盖初始加载、空数据、搜索无结果、错误与重试、取消及完成；记录实际完成量或显示不确定进度。错误后保留用户输入。

动效说明目的、触发、时长与中断方式。优先使用短反馈，新动作可反向或替换前一动画；动画结束前仍应能操作窗口。减少动效时直接切换并保留文字反馈，具体方法见[动效决策](motion.md)。

借鉴 Motion.Lab、Motion Hub 等动效网站的搜索分类、主题、标签或检查器时，按[界面与动效转化](interface-motion.md)把结构映射到主任务。卡片、留白和动态装饰随数据密度取舍；先确定语义、焦点和稳定命中区，再安排过渡。

沿键盘路径检查 Tab/Shift+Tab、方向键、Enter、Esc、菜单键和批量选择，核对屏幕阅读器的角色、名称与状态。中文输入法的组合输入不能误触回车提交。按目标环境检查 100%/150%/200% 缩放、混合 DPI 多屏、窄窗及最大化，注明实际运行、仿真、静图或待验证。

## 视觉示范的交付条件

先选一个真实主操作，写明用户从哪里开始、会改变什么、反馈出现在哪里。例如批量校验要同时看得见选中范围和任务结果。交付前在实际渲染画面上复核标题、主操作、数据和反馈的阅读顺序；确认选中、焦点和按下各自可辨，主操作不会随着回执出现而跳位。已有应用保留熟悉的导航和数据操作。

用至少两次快速连续操作检验动效：在上一段反馈结束前再次选择、切换或取消，界面应呈现最后一次意图且保持可操作；减少动效时仍要看得出结果。把实测截图与可点击入口或操作记录一起交付。报告区分样式意图、操作验证和用户对视觉风格的认可。示例的配色与图形属于该示例，后续产品按自身任务和用户偏好确定。
