# 交付、数据和清理

1. 依照已批准的交付方式记录实际依赖。安装 EXE/MSI 要测安装路径、非管理员或提升权限、升级与卸载；文件夹/ZIP 要从含空格和中文的新路径启动；单文件记录解包行为、冷启动和旁置数据；MSIX 检查签名、包标识和安装条件；源码需给出可复制的安装、运行、验证命令。在干净、断网目标机验证后才能声明离线开箱即用。
2. 应用目录按框架习惯组织。源文件和图标源稿进入源码管理，测试、文档、脚本按用途放置。packaging 保存可重建的打包配置；build/dist/bin 保存生成物；本地 releases 是经过检查的候选包和校验值；GitHub Releases 是独立授权的远端发布记录。不要从目录名推断正式发布。
3. 区分程序与用户数据目录。为设置、持久数据、缓存、可轮转日志和任务临时文件分别写出实际位置；以普通用户测试写权限。便携模式是否允许旁置、升级如何迁移、卸载保留哪些数据，以确认单为准。
4. 图标核实来源与许可，保留 SVG 等源件和所用字体/素材信息；从源稿输出多尺寸 ICO 或框架资源。逐一验证 EXE、窗口、任务栏、快捷方式和安装器的实际显示。没有相应交付物或真实 Shell 操作时分别记不适用/未验证。
5. 每次实际更新同步 CHANGELOG.md 和受影响文档。未发布条目进 Unreleased，写改动、用户影响、兼容性和升级事项；发布时才使用真实版本与日期。
6. 结束时先列出确定由当前操作生成且过时的项目。核实绝对路径、链接/重解析点、硬链接、资源调用和边界；优先按清单删除。未知文件单列保留。除非获授权，保留用户数据、依赖声明、许可、有效交付物、必要证据；Git 忽略状态不能证明文件可删。
7. 回归检查到真实入口，区别截图、代码审查、自动化和人工操作。原生拖放的 MIME/剪贴板测试不能证明鼠标拖出到另一程序。交付使用步骤、构建配置、系统/架构、校验值、清理和已知限制；区分通过/失败/未执行/环境受限。
