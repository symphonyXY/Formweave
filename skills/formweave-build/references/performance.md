# 可复查的性能记录

先与用户定义目标设备、典型/上限数据量、主操作和阈值。预算用例如“8 万行筛选 p95 ≤ 商定毫秒数”，未知时先测基线，再提目标。每条结果记 OS 构建、架构、CPU/RAM、电源/磁盘、提交或样例哈希、依赖、发布/调试构建、数据和步骤。

| 场景 | 方法 |
|---|---|
| 冷/热启动 | 分清系统冷启动、进程重启与已预热缓存；从启动进程到可接受首个输入分别计时。至少说明次数和分布。 |
| 空闲 | 窗口就绪后按固定时间点采样私有提交量和 working set；记录子进程数量。共享页重复统计时明确其含义。 |
| 典型与大数据 | 执行装载、排序筛选、跨页选择、缩放，记录主线程最慢操作、尾延迟及峰值。虚拟化减少视图对象，无法代替查库分页。 |
| 批量与持续运行 | 固定批量大小和并发，记录吞吐、取消延迟、句柄、CPU/I/O、退出后的孤儿进程。重复同一循环并等待回收，区分稳定平台、合理有界缓存与持续增长。 |

可用 [进程树采样器](../scripts/sample_process.py) 在任务期间对同一 PID 连续采样。它使用 Windows psutil 的 private（私有提交字节）和 rss（工作集），列出进程数；快照无法追回已退出子进程，受限样本须保留说明。按需另测首屏、输入延迟和 GPU。

先复现慢点，再试懒加载、模型视图/分页、按显示尺寸解码、限制缓存字节与任务并发。窗口关闭时停止接收更新、取消并回收任务；双击时避免重复提交，忽略过期结果，超时有恢复路径。比较优化前后须固定场景和统计口径，检查交换资源（如速度提高但内存增加）。没有基线/后测则报告为设计措施。
