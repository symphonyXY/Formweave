# 项目盘点与安全清理

## 盘点与增量整理

先确认目标工程根和本次是「只读检查」「整理工程」还是「准备交付」。读取项目指引、依赖与锁、构建和测试入口，识别项目实际已有的命名、编码、换行和数据格式。如果是子工程，不误把上级工作区的配置、测试或输出归到本项目。已有工程保留熟悉的布局；需要搬移文件时先列出引用方、构建规则、资源与发布路径，先验证基线，再小批修改并复验。新工程只建当下使用的目录，按目标框架约定补必要依赖声明、构建入口与用户文档，不复制与项目无关的工具链或文件清单。

用包内[交付盘点脚本](../scripts/project_check.py)快速识别常见入口和文档。需要 Python 3.13，无第三方依赖；没有 Python 可人工完成。以下命令从安装包根目录运行，将项目路径换为实际位置。`--profile open-source` 额外查许可、贡献文档并提示发布证据；默认不要求私有交付开放贡献。

```powershell
py -3.13 -B .\scripts\project_check.py 'D:\Projects\Inventory'
py -3.13 -B .\scripts\project_check.py 'D:\Projects\Inventory' --profile open-source --entry 'src/Inventory/Inventory.csproj' --json
```

脚本只读取目录条目和文件元数据，查看根目录、直接 `src`／`app` 入口及根、`docs`、`.github` 下的常用文档；不递归猜测框架，不加载项目脚本、不读应用数据、不运行 Git、不访问网络。`--entry` 可补充任意层级的明确入口。`--artifact` 只列调用者指定的项目相对文件及大小，不是可删清单。链接、重解析点、多重硬链接等不跟随。退出 `0` 仅表示报告已生成，`2` 表示参数、路径或读取错误；「发现」是存在证据，不是内容或应用验收通过。不把本工具接成自动格式化、删除或发布钩子。

按目标仓库自己的约定核对 `.editorconfig`、`.gitattributes` 和忽略规则；区分源码和锁文件、打包配置、可重建输出、测试夹具、运行时配置与用户数据。已有规则优先，数据编码、文件格式或路径迁移需另行确认并有回滚验证。适用时可用 [EditorConfig Checker v4.0.2](https://github.com/editorconfig-checker/editorconfig-checker/blob/v4.0.2/README.md) 只检查，不为一次收尾强制安装。

## 清理不是目录名匹配

1. 在生成前把一次性探针、截图副本和中间构建放进独立、明确的工作目录，记录自己生成的文件。结束时只对证据充分且不再需要的产物提出候选；保留维护用测试、测试夹具、许可证、凭据、用户文件、构建输入、有效交付品与必要证据。发现疑似废弃的既有文件单列为待确认，不能因未跟踪或被忽略而删除。
2. 清理清单先给真实绝对路径、来源、用途、可重建性和引用检查。仅在批准范围明确包括这份清单时执行；如范围、文件内容或路径发生变化，停止并重新预览。核对路径及祖先目录仍在约定根内，没有链接、重解析点或多重硬链接。优先逐项删除普通文件，只移除本操作创建且确为空的目录，不使用整仓库的 `git clean`、通配符或不明的递归清理。
3. 删除后比较清单与文件变化，从最终交付入口复验；安全性不能确认就保留。报告注明已删、保留、未验证和原因。只读盘点阶段无论报告结果如何都不执行删除。

仅借鉴 [Cargo 的受限目标目录与预览设计](https://github.com/rust-lang/cargo/blob/rust-1.92.0/src/doc/man/cargo-clean.md)，不调用其命令处理非 Cargo 项目。
