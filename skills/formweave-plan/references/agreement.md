# 范围确认单

先从聊天、项目指引、代码、运行说明和样例数据填写。确认可以在聊天内完成。避免要求用户重填资料或把已经明确批准的方案重新过一遍。

| 决策 | 会改变实现的问题 |
|---|---|
| 使用者与目标 | 谁在什么环境完成什么任务？最常见的路径、失败代价、必需项、优先级和本次边界是什么？ |
| 项目基线 | 当前框架、存储格式、更新程序、外部工具、原生拖放/剪贴板、自动化接口和用户数据有什么已用行为？选一条可复验的正常入口。 |
| 视觉与输入 | 目标风格、参考图、表格密度、鼠标/触摸/键盘、简体中文输入、缩放、多窗口与辅助技术要求？ |
| 平台与规模 | 记录 Windows 10/11 的版本和构建、x64/其他架构、内存、典型和峰值数据量、响应/内存预算、离线或受限权限。默认建议 Win10 22H2 x64 与 Win11 x64，需记下实际测试构建。 |
| 交付与更新 | 允许多选安装 EXE/MSI、文件夹/ZIP、单文件 EXE、MSIX、源码。分别问免安装、真正单文件、外部运行库、离线、写入位置、提升权限、更新与卸载数据保留。 |
| 图标与素材 | 自定义、沿用、自动生成三选一；自动生成先定名称、用途、风格、主色、参考偏好，需比选才做候选。核实来源许可。 |

汇总一份短约定：任务模式、目标用户和主路径、此次交付物及排除项、不可退化能力、架构/框架/组织及关键代价、可操作的验收标准和仍待验证的系统。把需用户决定的差异和推荐默认值放在一起。

“先给个方案”“可以试试这种风格”只支持相应的规划或预览。“确认按上面的方案开发”或用户在同一指令中明确批准了具体可验收范围，可进入该范围的实现。工作中改变平台、重写框架、改变数据行为或交付物时说明影响并重新确认；常规工程细节自主完成。
