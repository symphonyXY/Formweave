# Windows 界面审查

包内相对路径以本 SKILL.md 所在目录为基准。结论应与已有材料能够支持的证据一致。

## 环境

需截图、原型、源码或构建之一；截图审查无需运行框架，原生交互验证需要 Windows 和可运行环境。

## 执行

识别目标用户、核心任务、系统、评审对象和材料类型；先检查提供的路径或链接是否可访问。缺少材料时索取截图、原型或工程。按[桌面设计](references/desktop.md)检查主操作及最可能影响任务的例外状态。

每个发现记录定位依据、复现条件、观察结果、用户影响、优先级、改法与复验方法。阻止完成任务或存在数据风险的优先；其余按影响、频率和可绕过程度排序。区分观察、推断与待验证项。静态截图可支持层次、可读性和可见状态的判断；输入法、时序、耗时及可访问树需要相应运行证据。

保持审查范围。用户随后要求实施修复时，按[范围确认](references/agreement.md)核对已有批准。

## 交付

先列最影响主任务的发现，再说明未覆盖项。每个发现都应能定位、解释影响并复验；证据不足时给出补充材料和复验办法。没有发现问题时如实说明范围，不凑问题数量，也不把建议写成已完成的修复。
