# 从动效网站到桌面工作流

需要借鉴 Motion.Lab 或 Motion Hub 的界面、制作动效预览或比较参数时读取。具体效果按[来源导航](motion-index.md)查找；业务状态、中断与降级按[桌面动效决策](motion.md)处理。以下转化是 Formweave 的设计建议，不代表来源网站已经实现桌面行为。

## 界面方法怎样落到桌面

| 来源中可观察的方法 | 适合迁移的任务 | 桌面实现与取舍 |
|---|---|---|
| 两站将搜索、分类、结果数量放在内容上方 | 素材库、模板选择、日志或库存筛选 | 保留查询、分类、排序与数量的对应关系；无结果提供清除条件和焦点入口。数据表在原位更新，不因每次输入播放整屏入场。中文组合输入结束后再应用筛选；数据规模决定是否防抖或异步。 |
| Motion.Lab 卡片区分演示、名称说明与重播/调参/代码 | 低密度组件库、图表或效果挑选 | 卡片保留一个主动作；高级参数进入检查器，按需挂载当前预览。业务记录以表格/列表为先，卡片网格不替代密集编辑。离屏和后台暂停装饰循环。 |
| Motion Hub 画布配可收起的详情面板，提示词/实现示例分层 | 图片对比、编辑器、属性检查与设计预览 | 主画布保留操作空间，检查器表达当前选择；返回时恢复查询、滚动和焦点。窄窗转为可关闭侧栏，关闭后焦点回到入口。详情面板不遮挡保存、取消及错误。 |
| Motion.Lab 将参数值、单位与局部演示并置 | 调整过渡时长、距离和强度 | 参数改动只影响指定演示；提供恢复默认或记录基线的办法，比较时一次改一个变量。重播可以重置合成演示，业务页重播反馈不能重新提交命令、清空输入或重启任务。 |
| Motion Hub 用石板灰表面、单一蓝色强调、分类标记与主题切换 | 专注阅读和操作的工作区 | 将表面、正文、弱化文字、分隔线、强调、错误映射为语义令牌；深浅模式与强调色分别配置。焦点、选中和悬停各自可辨；成功/错误同时有文字。按实际密度调整圆角和留白，不强套网页大标题。 |
| Motion Hub 的分段标签高亮随目标移动 | 少量互斥视图与筛选 | 立即更新选中语义和内容，再移动背景指示器；控件文字、焦点和命中区固定。标签等宽不是前提，缩放、长中文标签或换行后重算位置。快速 A→B→C 以 C 为准。 |

两站的目录适合找方法，不能用点赞数、卡片颜色或演示复杂度决定业务优先级。演示文案、代码片段和实际渲染也可能不一致：Motion Hub 的“实现示例”明确说明只是预览标记与最小 CSS 起点，完整沙盒逻辑另在 data/motions.js。移植前检查实际行为，不能凭名称或提示词宣称功能已接通。

## 按桌面场景组合

| 场景 | 可查的来源＋ID | 组合方式与复验 |
|---|---|---|
| 列表选中后查看详情 | Motion.Lab `fade-in-up`；Motion Hub `fade-in-up` | 主表稳定、立即显示新数据，仅详情短淡入；快速选 A、B、C 后只能显示 C。参考网站较长的入场时长不直接照搬。 |
| 切换“全部 / 待处理 / 异常” | Motion Hub `sliding-indicator-tabs`、`layout-transition` | 指示器表达当前筛选；表格即时更新数量，低密度卡片可对可见项做小范围重排。焦点、键盘选择与滚动锚点跟随稳定记录 ID；被筛走的项退出命中和可访问树。 |
| 检查器展开与关闭 | Motion.Lab `accordion-smooth`；Motion Hub `spring-drawer` | 采用开合连续性，桌面入口可点击且可键盘触发，拖拽只是可选方式。Esc、反向切换、失焦及减少动效均到达同一终态；数据不依赖抽屉关闭动画保存。 |
| 批量校验与状态摘要 | Motion Hub `dynamic-island`、`circular-progress-meter`；Motion.Lab `lottie-checkmark` | 把紧凑摘要放到窗口内任务区或状态区，按需展开详情；根据执行器实际完成量更新数量和环形进度。未知总量显示不确定状态；成功、失败与取消有不同文本，不用模拟波形表示真实设备输入。 |
| 扫描件处理前后对照 | Motion Hub `before-after-slider`、`image-preview` | 图像遮罩跟随分隔手柄；提供键盘调整、原图/结果切换和固定详情预览。隐藏系统光标或必须悬停才能访问的内容不迁入桌面主路径。 |
| 深浅模式切换 | Motion Hub `theme-switch` | 可短暂插值表面色；立即更新主题语义、图标与文字，避免全屏亮闪。运行时减少动效、高对比度或透明关闭时直接换成可读终态。 |

## 留下一份可实施的约定

在现有方案或任务说明中记录必要字段，无需另建固定格式文件：

- 任务与状态：用户输入、受影响表面、起态、终态、真实数据来源；未选用动效时说明直接更新即可。
- 来源与改法：来源＋ID、原例表达的变化、保留的方法、舍弃的装饰；不把同名条目视作同一实现。
- 参数：本项目的 duration、distance、easing、stagger，以及单位和作用范围；区分上游默认与项目起点。
- 连续操作：新动作替换/反向/合并旧过渡，异步结果按任务或记录标识隔离；退出时停止循环与订阅。
- 等价终态：键盘和点击走同一命令，焦点与可访问状态如何变化，减少动效时怎样直接到达结果。
- 验收：一条正常路径、一条快速反向/重复路径和相关降级条件，注明真实运行或待测。

建议局部反馈先试 100–160 ms，内容切换 140–200 ms，面板开合 180–240 ms；位移先试 4–8 个逻辑像素。它们是可调整的 Formweave 起点，不是网站原值或通过性能测试的阈值。密集表格通常无需错开；少量首次分组若需 stagger，可先试 20–40 ms 并把总等待限制在约 240 ms 内。普通淡入/开合用 ease-out 起步，回退直接呈现；弹簧只用于能解释吸附或层级的少数表面，不给每个控件弹跳。

## 在四个工作流中传递

规划把主任务、界面结构、候选和验收写入已有方案；预览把同一条约定做成可切换的普通/减少动效两种表现，并用合成数据演示中断；开发沿用约定和当前框架，完成真实业务绑定；审查以同一触发与终态复验。约定已有批准即可沿用，不能把“参考这个站”推成框架迁移或改写数据行为的批准。

实现不要求引入网页动效库。Qt Widgets 可用单个 QPropertyAnimation 管理受影响表面，WPF 优先固定容器的 Opacity/RenderTransform，Electron 可用局部 CSS 或可取消的动画实例；已有其他框架沿用其状态机制。动画只负责表达，业务提交、取消和资源释放由业务生命周期保证。连续输入、滚动、窗口缩放和后台空闲分别验证；仅有 HTML 演示时，原生输入法、系统减少动效通知、辅助技术和 GPU 回退仍待目标环境验收。
